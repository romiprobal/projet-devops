Ce projet adapte une stratégie Trunk-Based donc branches courtes et intégration fréquante sur la branche principale 'main' (donc crée branches courte pour ql heure). Contrairement à Git Flow qui alourdit le processus avec pls branches (dev, feature, release) pls lourd, difficile à lire les logs, conflit etc...

Trunk based favorise l'intégration continue et s'aligne avec DORA

Donc performent car en DevOps se mesure à travares 4 indicateur

Deployement Frequency - frequence du push du code en production
Lead Time for Changes - temps d'un commit pour arriver en prod
Change Failure Rate  - pourcentage déploiement erreur
Time to Restore Service (MTTR)  - temps pour réparer le prbl
